Training Pipeline — Study Guide

What depression_detection_pipeline.py does, step by step. Each step has a simple explanation first, then the real version with the function names. Words in the glossary are linked.

The big idea in one paragraph Imagine you want to teach a robot helper to tell whether a cancer patient is feeling depressed, just from their answers to two questionnaires. You have answer sheets from about 1,531 real patients. You tidy the sheets, write the correct answer on each one (depressed or not, and how much), let the robot practise on most of the sheets, and then test it on sheets it has never seen. If it does well, you save its "brain" to a folder so the app can use it later. That's the whole script.

inRaw survey data

It's a giant spreadsheet. Each row is one patient. Each column is one question they answered, like "How sad do you feel?" or "How often do you worry the cancer will come back?"

What the code actually does

  • main() reads Data/cancer_psychology.csv with pd.read_csv.
  • It contains 21 BDI items (depression), 42 FCRI items (fear of cancer coming back) and demographic columns (gender, age group, cancer type, stage and so on).

1Clean & convert

Computers can't do maths with words like "a few times a week", so we swap each answer for a number. We also cross out names so the robot never knows who anyone is, throw away sheets that are mostly blank or were filled in without reading, and fill in a few small gaps with a sensible guess.

What the code actually does

All of this lives in ClinicalDataPreprocessor.fit_transform(), in this order:

  1. Find the columns (_identify_columns): spots BDI, FCRI and demographic columns by name.
  2. Drop personal info: removes Name, Timestamp and Patient ID (PII).
  3. Text → numbers (_parse_bdi, _parse_fcri): BDI answers become 0–3 by matching key phrases. FCRI answers become 0–4 using FCRI_SCORE_MAP ("never" = 0 … "all the time" = 4).
  4. Drop mechanical responders (_drop_mechanical): someone who answered 0 to every FCRI question probably didn't read them.
  5. Reverse item 13 (_reverse_fcri_item_13): "I believe I am cured" points the opposite way to every other question, so its score becomes 4 − answer. Now a high number always means more fear.
  6. Drop mostly-empty rows (_drop_excessive_missing): more than 50% of questions blank → removed.
  7. Fill small gaps (_impute_subscale_means): a blank answer gets the average of that patient's other answers in the same section (imputation). If fewer than half of a section was answered, the patient is dropped instead.
  8. Encode demographics (_encode_categoricals): words like "Breast", "Lung" become 0, 1, 2… with a LabelEncoder.
Why does step 4 come before step 5?If we reversed item 13 first, an all-zero patient's item 13 would become 4, so they'd no longer look "all zero" and would slip through the check.

Words to know: PII · imputation · encoding · subscale

2Create labels

To learn, the robot needs an answer key. We add up each patient's 21 BDI scores. If the total is 11 or more, we write "depressed" on their sheet. We also write how much, using six levels from "Normal" to "Extreme".

What the code actually does

TargetVariableEngineer.create_targets() adds three columns:

  • bdi_total: sum of the 21 BDI items (0–63).
  • has_depression: 1 if bdi_total ≥ 11, else 0. This is the binary label.
  • depression_severity_encoded: one of 6 bands. This is the multiclass label.
BDI totalSeverity band

Words to know: label / target · binary vs multiclass

3Build the feature matrix

Now we decide what the robot is allowed to look at when guessing. That's the clues (features). The answer key (label) is kept separately so the robot can check itself.

What the code actually does

  • feature_cols = BDI item columns + FCRI item columns + the *_encoded demographic columns.
  • X = df_fin[feature_cols].fillna(0): the table of clues, one row per patient.
  • y_bin and y_multi: the two answer keys.
Watch out: an examiner may ask about thisThe label is calculated from the BDI items (their sum), and those same 21 items are also in X. So the model can more or less "add up the answer key", which is part of why binary accuracy is so high (around 99%). This is called label leakage. Be ready to explain it: the FCRI and demographic columns add information, but the BDI items alone nearly decide the label.

Words to know: feature · label · leakage

4Split 80 / 20

If a teacher gave you the exact exam questions to practise, a perfect score wouldn't prove you learned anything. So we hide 20% of the sheets in a drawer. The robot practises on the other 80%, and the hidden 20% become its final exam.

What the code actually does

  • train_test_split(X, y_bin, test_size=0.2, stratify=y_bin, random_state=42).
  • Stratified means both piles keep the same mix of depressed and not-depressed patients. That matters because "No Depression" is rare (about 5.6%).
  • The same split is reused for the multiclass labels (y_multi.loc[X_train.index]), so both tasks are tested on exactly the same patients.

Words to know: train / test split · stratified · class imbalance

5Scale features

Some clues go from 0 to 3, others from 0 to 4, and encoded demographics can go higher. That's like comparing centimetres with metres. Scaling puts every clue on the same ruler so no clue looks more important just because its numbers are bigger.

What the code actually does

  • StandardScaler changes each column so its average is 0 and its spread (standard deviation) is 1.
  • fit_transform on the training set only, then transform on the test set. The scaler learns averages only from practice data, so no information from the exam leaks in.
  • One scaler is shared by both tasks and saved for the app.

Words to know: StandardScaler · fit vs transform

6Train 3 models + ensemble

Instead of one robot, we train three different kinds, each with its own way of thinking. Then we let them vote. For each robot we also try different settings to find the ones that work best. We do all of this twice: once for "depressed or not?" and once for "how much?".

What the code actually does

DepressionClassificationPipeline.train() is called with task='binary' and again with task='multiclass'.

ModelSimple ideaSettings tried
Logistic RegressionGives each clue a weight, adds them up, turns the total into a probabilityC: 0.01, 0.1, 1, 10
Random ForestMany decision trees, each sees slightly different data, then they votetrees 100/200, depth 5/10/none, min split 2/5
XGBoostTrees built one after another, each fixing the last one's mistakestrees 100/200, depth 3/5/7, learning rate 0.01/0.1
  • Tuning: GridSearchCV tries every combination of settings using 5-fold cross-validation, and picks the one with the best macro-F1.
  • Fairness to rare classes: class_weight='balanced' for LR and RF, and matching sample_weight for XGBoost, so mistakes on rare classes count more (class imbalance).
  • Ensemble: a soft-voting VotingClassifier averages the three models' probabilities. Binary uses equal votes. Multiclass gives Logistic Regression a double vote (weights=[2,1,1]) because it was clearly the strongest on its own.

Words to know: model · hyperparameter · GridSearchCV · cross-validation · ensemble · soft voting

7Feature importance

After training, we ask the tree robots: "Which questions helped you most?" If a few questions do most of the work, a phone app could ask only those and save the patient time.

What the code actually does

  • FeatureImportanceAnalyzer.extract() takes feature_importances_ from the binary Random Forest and XGBoost, scales each to sum to 1, and averages them.
  • report_top() prints the top 5 BDI and top 5 FCRI items. The full ranking is saved to models/feature_importance.csv.

Words to know: feature importance

8aEvaluate on the test set

Exam day. We open the drawer with the hidden 20% and let every robot guess. Then we count how many it got right, and what kind of mistakes it made.

What the code actually does

  • ModelEvaluator.evaluate() scores all 4 models (LR, RF, XGB, ensemble) for each task: accuracy, precision, recall, F1 (weighted averages) and ROC-AUC.
  • plot_confusion() saves confusion matrices to models/binary_confusion.png and models/multiclass_confusion.png.
  • At the end, the "best" model for each task is the one with the highest weighted F1.

Words to know: accuracy · precision · recall · F1 · ROC-AUC · confusion matrix

8bTune the binary threshold

The ensemble doesn't say just "yes" or "no". It says something like "I'm 70% sure this person is depressed." Normally anything over 50% counts as yes. But because healthy patients are rare, the robot is bad at spotting them. So we try many cut-off lines and keep the one that is fairest to both groups.

What the code actually does

  • tune_binary_threshold() uses cross_val_predict to get out-of-fold probabilities on the training set only.
  • It tries 91 thresholds from 0.05 to 0.95 and keeps the one with the best macro-F1.
  • The test set is only used afterwards to report how the chosen threshold does, never to pick it. That keeps the exam honest.

Words to know: threshold · macro-F1 · cross-validation

9Export to models/

The robots have learned, so we save their brains into a folder. Later, the app opens the folder and uses them straight away, without having to learn everything again.

What the code actually does

ModelEvaluator.export() is called once per task and writes:

  • {binary|multiclass}_{model}_model.joblib: 4 models × 2 tasks = 8 files (joblib).
  • {task}_scaler.joblib: the scaler from step 5.
  • label_encoders.joblib: the demographic encoders from step 1.
  • feature_metadata.json: the exact column order (feature_cols), each column's training average (feature_means, used to fill missing inputs) and the tuned binary_threshold.

predict_depression.py and the Streamlit app only read these files. They never retrain.

Glossary

Accuracy
Out of all guesses, how many were right. Can be misleading when one class is rare: always guessing "depressed" would already score about 94% here.
BDI (Beck Depression Inventory)
A 21-question depression questionnaire. Each answer scores 0–3, so the total is 0–63. Higher means more depressed.
Binary vs multiclass
Binary: two possible answers (depressed / not). Multiclass: more than two (here, six severity bands).
Class imbalance
When one answer is much rarer than another (here, "No Depression" is about 5.6%). A lazy model can ignore the rare class, so we give it extra weight with class_weight='balanced'.
Confusion matrix
A table of real answer vs predicted answer. The diagonal holds the correct guesses, and everything else shows which classes get mixed up.
Cross-validation (k-fold)
Cut the training data into 5 pieces. Train on 4, test on the 5th, and repeat so every piece gets a turn. The average score is more trustworthy than one lucky split. "Stratified" k-fold keeps the class mix the same in each piece.
Encoding (LabelEncoder)
Turning categories into numbers: "Female" → 0, "Male" → 1. Models only understand numbers.
Ensemble
Combining several models into one team. Different models make different mistakes, so together they are often steadier.
F1 score
A single score that balances precision and recall (their harmonic mean). It is only high if both are high.
Macro-F1 vs weighted-F1
Macro: F1 for each class, then a plain average, so every class counts equally, even rare ones. Weighted: the average is weighted by how many examples each class has, so big classes dominate. Tuning uses macro so the rare class isn't ignored.
FCRI (Fear of Cancer Recurrence Inventory)
A 42-question survey about fear of the cancer coming back. Each answer scores 0–4. It's grouped into 7 subscales: triggers, severity, psychological distress, functioning impairments, insight, reassurance, coping strategies.
Feature
One clue the model looks at, i.e. one column of X (for example, the answer to BDI question 4).
fit vs transform
fit = learn something from data (for example, column averages). transform = apply what was learned. You fit on training data only, then transform both train and test.
GridSearchCV
Tries every combination of the hyperparameter values you list, scores each with cross-validation, and keeps the best one.
Hyperparameter
A setting you choose before training (number of trees, tree depth, C), as opposed to what the model learns by itself.
Imputation
Filling in a missing answer with a sensible guess, here the average of the same patient's other answers in that section.
Feature importance
How much each clue helped the tree models make decisions. High importance means the model relied on it a lot.
joblib
A Python tool that saves a trained model to a file and loads it back later, exactly as it was.
Label / target
The correct answer the model is trying to predict (y). Here: has_depression or the severity band.
Label leakage
When the clues secretly contain the answer. Here the label is the sum of the BDI items, and those items are also clues, so scores look better than they would on a truly independent label.
Logistic Regression
Gives each feature a weight, adds them up and squashes the total into a probability between 0 and 1. Simple, fast and easy to explain. C controls how strongly it is held back from over-fitting (smaller C = more careful).
Model
The "robot brain": a maths recipe that turns features into a prediction, with numbers learned from the training data.
PII (Personally Identifiable Information)
Anything that reveals who a person is, like their name or ID. It is removed so the model can't use it and patients stay private.
Precision
Of everyone the model said was depressed, how many really were. ("When it says yes, can I trust it?")
Random Forest
Many decision trees ("if answer 4 > 2, go left…"), each trained on a random sample of rows and features. Their votes are combined, so one tree's mistake gets outvoted.
Recall
Of everyone who really was depressed, how many the model caught. ("Does it miss people?") In screening, missing a depressed patient is costly, so recall matters a lot.
ROC-AUC
How well the model ranks positives above negatives across every possible threshold. 1.0 = perfect, 0.5 = coin flip. For multiclass it is averaged one-vs-rest.
StandardScaler
Rescales each column to mean 0 and standard deviation 1: (value − mean) / std.
Soft voting
Each model gives probabilities, and they are averaged (optionally weighted). The class with the highest average wins. Hard voting would just count yes/no votes.
Stratified
Splitting so each part keeps the same proportion of each class as the full dataset.
Subscale
A group of related questions inside a questionnaire (FCRI has 7). Its items are summed to measure one specific thing.
Threshold
The probability cut-off for saying "yes". The default is 0.50, and this pipeline tunes it to maximise macro-F1.
Train / test split
Training set = practice questions the model learns from. Test set = the locked exam, used only once at the end to measure real performance.
XGBoost
"Extreme Gradient Boosting". Builds small trees one after another, each focused on fixing the previous trees' errors. The learning rate controls how big each fix is.

Check yourself

1. Why is the scaler fitted only on the training set?

If it learned averages from the test set too, information from the "exam" would leak into training and the test score would look better than reality.

2. Why tune with macro-F1 instead of accuracy?

"No Depression" is only about 5.6% of patients. Accuracy would reward a model that ignores that class. Macro-F1 treats every class equally.

3. What's the difference between soft and hard voting?

Soft averages the models' probabilities. Hard just counts their final yes/no votes. Soft uses how confident each model is.

4. Why is the threshold chosen on the training set and not the test set?

Choosing anything using the test set turns it into training data, so it no longer gives an honest final score.

5. Why is FCRI item 13 reversed?

"I believe I am cured" means less fear when agreed with. Reversing it (4 − score) makes high = more fear, like every other item.

6. Why might binary accuracy be close to 99%?

The label is the sum of the BDI items, and those items are also features (label leakage). The model can nearly recompute the label.

7. What does feature_metadata.json give the app?

The exact feature order, the training averages used to fill missing inputs, and the tuned binary threshold.
